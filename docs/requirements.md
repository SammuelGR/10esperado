# Requirements Sources

| Source | Role |
| --- | --- |
| [Jira project board](https://10esperado.atlassian.net/jira/software/projects/DE/boards/1) | Operational project work and status. |
| [Software Requirements Specification (SRS)](https://10esperado.atlassian.net/wiki/spaces/10esperado/pages/12222465) | Product overview, scope, user roles, and references to the requirements maintained in Jira. |
| Jira requirements and subtasks | Detailed specifications, business rules, and acceptance criteria for implementation. |
| [Release 1 baseline](https://10esperado.atlassian.net/wiki/spaces/10esperado/pages/15826945) | Approved delivery scope and specification snapshot at baseline capture. |

## Using the Sources

For a development task, read its Jira subtask, parent requirement, and any linked specifications needed to interpret its acceptance criteria. Consult the SRS for broader product context and the release baseline when determining delivery scope.

The Release 1 commitment is defined by its selected subtasks, rather than every operation in their parent requirements. Jira remains the source for current work and status.

If current specifications differ from the baseline in a way that changes the requested delivery scope, ask for clarification before implementing that difference.
